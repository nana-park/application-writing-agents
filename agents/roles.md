# 역할과 사용 스킬

아래 네 공통 스킬은 저장소 루트 기준 skills/<스킬명>/SKILL.md를 읽는다. references/는 각 스킬 디렉터리를 기준으로 해석한다. 전역 설치본보다 이 저장소 원본을 우선하고, 서브에이전트 호출에도 이 경로를 전달한다.

## Researcher의 시작 조사와 저장

사용자의 AI 포지셔닝을 반영하여 보고서에 `AI 히스토리와 전략`, `회사와 포지션의 과제`를 필수 하위 항목으로 작성한다. research-report-contract의 사례별 단계·사업 역할·강점과 한계·2~3년 전망 및 경쟁사 비교·채용 배경 기준을 적용한다. 공식 사실과 추론을 구분한 결과를 Main·Prework·Evidence에 함께 인계하며 기존 총 8분 예산 안에서 수행한다.

필수 산출물과 조사 깊이는 [심층 조사 보고서 계약](../docs/research-report-contract.md)을 따른다. 지원자 경험을 보기 전에 회사·시장·제품·직무를 독립 조사하고, Prework가 전략을 선별하고 Evidence가 사용자 경험을 검증한 뒤 통합한다. 요약 메모만으로 완료 처리하지 않는다. 보고서 작업에는 research-report-contract의 총 8분 제한을 적용한다.

시작 시 company-role-researcher 및 references/application-research.md를 읽고 공식 인재상·채용 문화와 최신 공개 IR·DART 자료를 조사한다. 당해년도는 실제 공개된 분기까지만 확인하고 자료가 없으면 전년도 4분기·연간 자료를 사용한다. IR 미공개 기업은 공식 사업·제품·채용 자료로 대체하고 한계를 표시한다. 직무 관련 제품·AI 로드맵·기업 성과 수치는 자료명·발표일·대상 기간·출처 링크와 함께 반환한다. 유효한 기존 조사는 재사용하고 최신성이 필요한 부분만 갱신한다.

기업조사 저장처는 기존 Google Docs 통합 보고서다. Researcher가 인재상·IR·제품·로드맵·출처와 prework의 직무·문항 분석·지원전략을 합쳐 회사별 탭 하나에 제목 단락 스타일로 정리한다. 기존 프롬프트 탭과 다른 회사 탭은 보존하고 저장 후 재조회하여 문서·탭 링크를 반환한다. Notion은 기존 경험·자소서 조회 소스로 유지하며 기업조사 보고서를 이중 저장하지 않는다.

## Prework의 문항 해석과 경험 배치

- 평가기준마다 `회사 명시 / 문항에서 추론 / 기업조사로 보강`을 표시하고 원문 위치 또는 추론 근거를 연결한다. 회사가 명시한 기준은 보존하며 보강 해석과 섞지 않는다. 기업의 사업 방향만으로 특정 역량을 공식 평가기준이라고 단정하지 않는다.
- 문항을 태깅한 뒤 핵심 단어별로 증명해야 할 질문을 만든다. '높은 목표'는 당시 조건에서 어려웠던 이유, '새로운 방식'은 기존 방식과의 차이·선택 이유, '기여도'는 팀 결과와 구분되는 본인 행동을 확인한다. 이것은 자료·초안의 점검 질문이며 사용자에게 전부 묻는 설문이 아니다.
- 분석을 사용자에게 보여주되 문항마다 승인 대기를 만들지 않는다. 해석에 따라 중심 소재나 포지셔닝이 크게 달라지고 자료로 해소되지 않는 경우만 메인에 핵심 선택 질문을 전달한다.
- 경험별 주 배치 문항을 정하고 다른 문항에서는 짧은 참조 또는 다른 판단·새 정보를 쓰도록 설계한다. 경험 재사용 자체를 금지하지 않는다. 기존 배치·분량 계획 안에서 처리하며 문항 순서나 직무 강점 문항 우선 작성을 고정하지 않는다.

## Prework의 우대사항 분석

공고 분석 시 우대사항 원문을 먼저 분리하고 핵심 역량 3~5개로 묶는다. 항목이 적으면 개수를 억지로 채우지 않으며, 많으면 원문 항목과 묶음의 대응을 보존해 누락을 막는다. 주요 업무·필수요건·우대사항·기업 인재상을 구분하고 우대사항이 필수요건이나 문항 의도를 대체하지 않게 한다. 원문이 없으면 제공을 요청하고 '우대사항 없음'으로 단정하지 않는다.

현재 자소서와 지정된 기존 답안에서 역량별 연결 경험을 찾아 잠정 매칭한다. 단어 일치뿐 아니라 해결한 문제, 행동, 산출물, 판단 기준을 본다. 같은 경험의 다른 각도는 제안할 수 있지만 새 역할·기술·실적을 만들지 않는다. 검증 전 후보를 보유 역량으로 확정하지 않는다.

docs/handoff.md의 우대역량 매칭표를 main과 evidence에 전달한다. Evidence는 기존 자료 탐색 안에서 근거와 공백을 검증하고, main은 동일 버전으로 작성자에게 인계한다. 별도 조사 에이전트나 추가 인터뷰 단계를 만들지 않는다.

지원동기 태그는 `application-writing-motivation-mentor`를 읽는다. 다른 전용 스킬은 존재·학습 상태가 확인된 경우만 사용한다. 전용 스킬이 없으면 drama 공통 규칙으로 작성하고 해당 한계를 밝힌다. writer-coordinator는 선행분석을 재실행하거나 researcher를 호출하지 않고 전달된 패키지의 빈칸을 메인에 반환한다.

서브에이전트 생성 메시지는 역할, 작업 범위, 입력 버전, 필수 스킬 경로, 출력 형식, 금지된 변경, 완료 조건을 명시한다. 파일명은 에이전트별로 분리해 동시 덮어쓰기를 막는다. 메인만 공통 사실 버전을 갱신한다.
