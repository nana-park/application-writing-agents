# 입력란별 작성 규칙

application-form-writer의 career.md, projects.md, education.md에서 문안 작성 규칙을 이관했다. 브라우저 조작, 자동완성 선택, 화면 검증, 사이트 임시저장과 제출은 이 문서의 범위 밖이다. 과거 실습의 완료 상태를 현재 지원서의 완료로 취급하지 않는다.

## 공통

- 문안 작성 전 SKILL.md의 `작성 재료의 우선순위와 실행 순서`를 따른다. ① Docs 지원전략 → ② 해당 Notion 구역의 다른 회사 작성 이력 전체 → ③ 경험자료 탐색 → ④ JD 원문 표현 적용 순서로 진행한다. 일반적인 JD 유사어 치환만으로 완료하지 않는다.

- 시작 전에 회사·직무·JD와 입력란별 총 글자 수, 별도 필드, 줄바꿈 허용 여부를 확인한다. 이미 확인했으면 재질문하지 않는다. 제한은 실제 양식마다 확인한다.
- 명사형·목록형으로 작성한다. 자소서처럼 포부나 장문 서사를 붙이지 않는다. 상세내용에 가운데 점 대신 쉼표나 `및`을 쓰며 긴 대시는 쓰지 않는다. 하이픈은 수행내용과 성과 또는 부연을 분리할 때 제한적으로 사용한다.
- 제목·개요·목표·성과·공백·줄바꿈을 포함한 실제 입력 문자열 전체로 글자 수를 계산하고 기준을 표시한다. 사이트가 다른 계산법을 쓰면 실제 기준을 따른다. Markdown 보관용 장식과 복사할 실제 문안을 구분한다.
- JD 반영 → 형식·분량 조정 → JD 용어 최종 대조 → 전체 글자 수 확인 후 저장 또는 웹 입력 담당에게 넘긴다. 웹에 먼저 넣고 잘린 문장을 고치는 방식으로 분량을 맞추지 않는다.
- 실제 수행과 대응하는 JD 용어만 사용한다. 직접 경험, 전이 가능한 경험, 근거 없는 요구조건을 구분한다. 단어 일치 때문에 산업·대상·책임을 바꾸지 않으며 용어 대응을 지원 자격 충족으로 간주하지 않는다.
- 글자 수 상한을 채우기 위한 군더더기는 금지한다. 사용자가 분량 보강을 원하면 원문에서 누락된 실제 업무·방법·규모·성과를 추가한다. 근거가 없으면 짧게 유지한다.

## 경력 담당업무

### 원문과 수정 범위

- Notion 직장경력 표의 회사·고용형태·기간·부서를 최신 담당업무 정리본과 대조한다. 같은 회사라도 고용형태와 기간이 분리된 경력은 임의로 합치거나 중간 공백을 재직기간으로 계산하지 않는다. 누락 이력과 의도적 제외를 구별한다.
- 지원전략을 읽은 다음 Notion 담당업무의 회사별 작성 이력 전체를 먼저 읽고 재료로 모은다. 이후 Drive 기준 이력서·경력기술서 등 허용 경험자료에서 부족한 업무를 보완한다. 최신본만으로 작성하지 않으며 이미 확인한 변하지 않은 원문은 재사용한다.
- 기본 구성은 제목, 주요 업무, 업무성과, 담당제품, 대표 프로젝트다. 사용자가 직무 항목을 추가하거나 승인한 다른 구성을 만들었다면 그 최신 형식과 번호를 유지한다.
- JD 맞춤 수정은 주요 업무를 우선 대상으로 한다. 제목·성과·제품·프로젝트는 원문을 유지하되 아래 분량 규칙 또는 사용자가 승인한 변경을 적용한다. 수치나 역할을 버전끼리 섞지 않는다.

### 길이와 문장 형식

- `업무명: 상세내용, 상세내용` 형식. 업무명은 10자 이내다.
- 업무별 상세내용은 최대 3개, 각각 약 20자다. 20자는 콜론 뒤 한 줄 전체가 아니라 쉼표로 나눈 개별 상세업무의 길이다.
- 경력마다 주요 업무 3개를 우선 확보한다. 상세내용을 의미 없이 잘게 줄이지 말고 세부 개수와 표현을 조절한다. 확인된 업무가 부족하면 개수를 맞추려고 만들지 않는다.
- 대표 프로젝트는 수행내용과 성과를 ` - `로 분리할 수 있다. 협업 국가 등 구체 정보를 원문이 뒷받침하면 보강한다. 비율과 퍼센트포인트의 변경은 단순 문체 수정이 아니다.

### 분량 초과 시

- 주요 업무 3개를 먼저 확보하고, 주요 업무보다 업무성과 구역을 먼저 축소한다. 담당제품과 대표 프로젝트는 기본 유지한다. 이는 주요 업무 줄 수부터 줄이던 옛 규칙보다 우선한다.
- 항목 삭제는 현재 JD 관련성과 사용자 승인 범위에 따라 판단한다. 이전 지원의 예외를 새 지원에 자동 적용하지 않는다.
- 담당제품 생략도 특정 경력에 승인된 예외이며 모든 경력에 확대하지 않는다. 적용하면 번호를 정리하고 확보한 분량을 주요 업무의 구체화에 배분한다.
- 담당제품이 빠지면 대표 프로젝트만으로 대상 사용자와 용도가 읽히는지 확인한다. 불명확한 내부 제품명은 승인 범위에서 짧게 보충하되 역할과 성과 수치는 유지한다.
- 필수 정보와 핵심 업무를 보존하면서 제한을 맞출 수 없으면 충돌을 알리고 필요한 선택만 질문한다. 임의로 잘라 저장하지 않는다.

## 경험·프로젝트

- Notion 직장경력 아래 프로젝트 토글 최신본을 기준으로 한다. 오래된 담당업무 요약으로 대체하지 않는다. 프로젝트명·근무처·기간·역할·목표·수행내용·성과를 현재 필드와 대응시킨다.
- JD 맞춤 수정은 수행내용에 적용하고 목표·성과·기본정보는 원문 유지가 기본이다. 사용자가 별도 수정을 승인하면 그 범위만 변경한다.
- 프로젝트명 칸이 없으면 본문 맨 위에 `[프로젝트명]`을 쓰고 한 줄을 비운다.
- 근무처·기간·역할 중 별도 칸이 없는 정보만 `1. 개요`에 넣고, `2. 목표 → 3. 수행내용 → 4. 성과`로 구성한다. 별도 칸이 모두 있으면 `1. 목표 → 2. 수행내용 → 3. 성과`를 유지한다.
- 수행내용은 `업무명: 상세내용` 형식이며 업무명은 10자 이내다. 상세내용은 최대 2개다. 2개이면 각각 약 20자, 1개이면 약 30자로 작성하고 명사형으로 끝낸다. 경력의 최대 3개 규칙과 혼동하지 않는다.
- 전체 제한 초과 시 수행내용부터 압축한다. 그래도 초과하면 JD상 중요도가 낮은 수행항목을 하나씩 제외한다. 목표·성과·필수 기본정보부터 줄이지 않는다. 경력의 업무성과 우선 축소 규칙과 혼동하지 않는다.
- 사용자 지정 순서를 유지한다. 등록 개수 제한이 있으면 입력 후보와 제외 후보를 보여주고 선택을 받는다. 임의 누락하거나 특정 사이트의 5개 제한을 일반화하지 않는다.

## 학력 주요성과, 연구, 활동·수상

- 통합 주요성과 한 칸이면 사용자가 지정한 경험 자료의 통합 요약을 기준으로 주요 논문·산학협력과제·수상 구조와 서지정보를 보존한다. 개별 연구 장문 설명을 전부 붙이지 않는다.
- 논문마다 별도 입력할 수 있으면 논문/특허의 최신 개별 정리본을 사용한다. 연구분야는 확인된 사용자 지정값을 유지하고 JD에 맞춰 임의로 바꾸지 않는다.
- 연구 상세 설명은 SKILL.md의 연구 원문 보존 규칙을 따른다. 기존 상위 번호 항목명·순서와 개요, 연구배경(문제정의, 목표설정), 연구결과는 유지하고 JD 맞춤 수정은 대괄호 요약 제목, 연구 수행내용, 시사점의 내용에 적용한다. 시사점은 확인된 연구결과의 직무상 활용 의미를 조정하며 상위 항목명은 유지한다. 연구 수행내용의 `① 업무명: 상세내용`은 업무명과 상세내용 모두 JD 맞춤 수정 대상이며, 보존 대상인 상위 번호 항목명과 구분한다. 공식 논문명은 바꾸지 않는다. 학력 요약, 경력 담당업무, 프로젝트 수행내용을 같은 양식으로 통일하지 않는다.
- 활동·수상은 현재 양식의 제한과 기존 항목 구조를 유지하며 역할·실제 수행·결과를 명사형으로 정리한다. 팀 구현물을 개인 구현으로 쓰지 않는다. 경력·프로젝트의 상세내용 개수 제한을 자동 적용하지 않는다.
- 모든 유형에서 원문은 보존하고 회사별 수정본은 SKILL.md의 Notion 보관 절차로 저장·재조회한다.
