# 경험·프로젝트 입력

- 지원서의 경험 또는 프로젝트 구역에는 Notion 경험정리의 직장경력 아래 프로젝트 토글 최신본을 사용한다. 오래된 담당업무 요약으로 대체하지 않는다.
- 원문의 프로젝트명, 근무처, 기간, 역할 및 목표·수행내용·성과를 확인하고 현재 양식의 실제 필드와 대응시킨다. JD에 맞춘 수정은 수행내용에만 적용하며 나머지는 원문을 유지한다.
- 프로젝트명 칸이 없으면 활동내용 맨 위에 `[프로젝트명]`을 쓰고 다음 구역까지 한 줄을 비운다.
- 근무처·기간·역할 중 별도 칸이 없는 정보는 필수 내용이다. `1. 개요`를 만들고 해당 정보만 그 아래에 넣는다. 이후 `2. 목표`, `3. 수행내용`, `4. 성과`로 번호를 조정한다. 별도 칸이 모두 있으면 원문의 `1. 목표`, `2. 수행내용`, `3. 성과`를 유지한다.
- 회사명 검색 필드는 자동완성 목록에서 정확한 회사를 선택하고 다른 칸으로 이동한 후 값 유지 여부를 확인한다.
- 입력 전에 제목·개요까지 포함한 전체 글자 수를 계산한다. 한도를 넘으면 기본정보를 누락하거나 임의로 문장을 잘라 저장하지 않는다.
- 등록 개수 제한으로 모두 입력하지 못하면 현재 입력 목록과 제외된 목록을 알리고 사용자에게 선택을 요청한다. 제한은 현재 사이트에서 확인한다.
- 구역 상단부터 화면을 캡처해 실제 표시 순서, 제목 뒤 빈 줄, 개요와 번호, 회사명과 기간을 확인한다. DOM에서 날짜가 빈 값처럼 보여도 화면으로 판단한다.
- 임시저장 성공 메시지를 확인한다. 일부만 입력한 상태라면 전체 완료로 보고하지 않는다.
- 개인 프로젝트 원문과 비공개 URL은 공유 스킬이나 Git에 복사하지 않는다.

## 작성 및 입력 순서

1. 작성에 앞서 해당 입력란의 총 글자 수 제한을 확인한다. 제목·개요·목표·성과와 공백·줄바꿈까지 전체 분량에 포함한다.
2. 최신 원문의 수행내용만 JD에 맞춰 1차 수정한다. 근거 없는 업무·책임·성과를 추가하지 않는다.
3. 수행내용은 `업무명: 상세내용` 형식으로 작성한다. 콜론 앞 업무명은 10자 이내, 뒤의 상세내용은 최대 2개다. 상세내용이 2개이면 각각 20자 내외, 1개이면 30자 내외로 쓰며 명사형으로 끝낸다. 경력 규칙의 가운데 점·대시 제한도 적용한다.
4. 전체 글자 수가 초과하면 수행내용을 먼저 압축한다. 그래도 초과하면 JD상 중요도가 낮은 수행내용 항목을 하나씩 삭제한다. 목표·성과·필수 기본정보를 먼저 줄이지 않는다.
5. JD와 용어가 맞는지 최종 대조하고 전체 글자 수를 다시 확인한다. 이 두 검토를 마친 문안만 웹에 입력한다. 일단 입력하고 반복 수정하는 방식으로 분량을 맞추지 않는다.

등록 순서는 사용자의 현재 선택을 따른다.
