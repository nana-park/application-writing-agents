# 문항 태그와 작성 스킬 연결

## 실행 순서

1. 선행분석 스킬을 먼저 읽고 실행한다. 지원 대상이 불명확하면 어느 회사의 어떤 직무에 지원하는지, 해당 공고 링크 또는 전체 JD를 요청한다. 이미 제공한 정보는 다시 요구하지 않는다. 전체 문항과 글자 수도 확보한다. 공식 공고의 직무·공고번호·기간을 대조하며, 다른 공고나 재공고로 임의 대체하지 않는다. 지원 화면에서만 보이는 문항은 사용자에게 복사본·캡처를 요청한다.
2. 기업조사는 company-role-researcher에 인계하고, 반환 결과와 현재 JD·전체 문항을 분석하여 문항의 직접 요구와 평가 의도를 잠정 분류한다. 같은 태그의 기존 자소서를 문항 분석 중 먼저 찾아 비교하되, 과거 답변에서 현재 공고의 의도를 역으로 만들어내지 않는다. 회사·직무·문항 분석을 마친 후 태그와 판단 근거를 확정한다.
3. 사용자가 지정한 Notion 경험정리의 자기소개서 페이지와 하위 DB만 기존 자소서 소스로 사용한다. DB 스키마를 확인하고 `질문` 다중선택 태그를 매칭한다. 제목 검색 결과만으로 답안을 읽었다고 하지 않고 선택한 페이지 본문을 확인한다.
4. 동일 태그를 먼저, 복합 태그 겹침·평가 의도·직무 관련성·분량을 다음 기준으로 후보를 고른다. 같은 태그가 없으면 인접 태그 후보임을 명시하고 확인한다. 검색 결과 없음과 접근 실패를 구분한다. 현재 지원과 무관한 기업명·포부·수치를 그대로 재사용하지 않는다.
5. 아래 경험 자료 순서로 사실과 디테일을 확인한다. 선행 리포트와 태그, 기존 답안의 채택·수정·폐기 이유, 선택한 경험과 빈칸, 분량 설계를 문항별 멘토에게 넘긴다.
6. 문항별 멘토는 공통 작성 스킬 `pm-drama-upgrade-mentor`의 STAR 등 경험 전개·디테일 질문·가독성·수치·분량·평가 원칙을 상속한다. 지원동기는 현재 `application-writing-motivation-mentor`로 연결한다. 전용 스킬이 없는 태그는 기본 스킬로 진행하며 전용 학습 완료를 주장하지 않는다.
7. 필요한 질문으로 근거를 확보한 후 A안(기존 자소서의 좋은 서사·표현을 더 많이 살려 현재 공고에 맞춘 안), B안(같은 검증된 사실에서 새 주장·경험 배치·문단 구조를 설계한 안)을 제시한다. 단순 동의어 교체로 두 안을 만들지 않는다. 각 안의 분량 설계를 먼저 보여주고 완성안, 차이, 추천 이유, 10점 평가를 비교한 뒤 사용자 선택을 기다린다. 근거 없는 새 경험을 만들지 않으며, 기존 답안이 없으면 A안을 억지로 만들지 말고 그 한계를 밝힌다.

## 태그 기준

현재 Notion의 `질문` 태그를 기준으로 한다. 새로운 태그를 임의로 저장하지 않는다.

| 태그 | 직접 요구와 핵심 평가 |
|---|---|
| 지원동기 | 왜 지금 이 회사·직무인지, 회사 선택과 상호 기여 |
| 회사선택기준 | 회사를 고르는 기준과 해당 회사가 맞는 근거 |
| 강점 | 채용해야 할 차별적 역량과 이를 증명하는 경험 |
| 협업 | 공동 목표 속 조율·갈등·역할·판단과 결과 |
| 성장과정 | 사건·인물이 현재의 태도와 판단에 준 변화 |
| 입사 후 포부 | 입사 후 기여·성장 방향과 현실적 실행 |
| 경력상세기술 | 담당 범위·실행·판단·성과와 본인 기여 |
| 사회이슈 | 이슈 선정 이유와 자신의 논리·견해 |

복합 문항은 주태그와 보조태그, 각 부분의 요구와 분량을 설명한다. 태그는 검색 경로이지 평가 의도 전체가 아니다. 예: 지원 이유와 입사 후 꿈은 `지원동기 + 입사 후 포부`. AI 강점을 요구하면 `강점` 아래 세부 평가축에 AI 판단·구체적 실행을 명시한다.

## 경험 자료의 우선순위와 경계

- 사용자 설명과 지정한 경험 자료의 현재 버전을 우선한다. 멘토 피드백과 사실을 구분하고 색상만으로 작성자를 추정하지 않는다.
- 사용자가 허용한 이력서·경력기술서·경험 자료로 누락된 연구·프로젝트·활동을 보완한다. 자료별 포함·제외 범위를 현재 요청으로 정한다.
- 나머지 Drive 프로젝트·논문 원문은 디깅 및 사실 검증용이다. Docs의 버전 이력 묶음과 하위 탭은 기본 제외하고 사용자가 과거 디테일을 요청할 때만 확인한다.
- 회사별·시기별 다른 문안은 같은 경험의 버전일 수 있다. 중복 계산하거나 여러 버전의 강한 주장만 합치지 않는다. 표현 변경과 사실 정정을 구분하고 기간·역할·지표가 충돌하면 원문 또는 사용자에게 해당 부분만 확인한다.
- 지정 경로 밖의 자소서, 불특정 로컬 작업본은 제외한다. 컨설팅 원문과 EDUCE 사례는 스킬 개선 때만 사용한다. 실제 작성에는 일반화된 작성 규칙을 적용한다.

## 문항별 스킬의 학습·공개 조건

새 문항별 스킬의 명명 규칙은 `application-writing-<question>-mentor`다. 지원동기 스킬 이름은 application-writing-motivation-mentor로 통일한다.

모든 신규 문항별 스킬은 공개·사용 가능으로 표시하기 전에 해당 태그의 2022년 이후 EDUCE 원문을 실제 읽고 분석해야 한다. 먼저 원문의 문항을 위 태그로 분류하고, 복합 문항은 다중 태그로 기록한다. 회사·직무·신입/경력·연도·글자 수·중복 여부도 구분한다. 제목 목록이나 후보 100건을 검증된 원문 100건으로 세지 않는다.

비공개 로컬에 원문 접근 근거, 사례 식별자, 태그, 분석 범위와 한계를 남기고, 스킬에는 반복 확인된 일반화 규칙만 반영한다. 원문·지원자 개인정보·회사 내부 정보는 공개 저장소에 넣지 않는다. 첫 문단, 문단 역할과 분량, STAR 활용·변형, 문장 호흡, 숫자 배치, 문항 간 일관성을 분석하고 실제 작성 예제로 기본 스킬과 충돌하지 않는지 검토한다.

기존 지원동기 스킬도 해당 태그의 원문 분석 근거를 확인하기 전에는 EDUCE 학습 완료로 간주하지 않는다. 학습 근거가 부족하면 기존 코칭 규칙으로 작업 가능한 범위와 원문 학습 미검증 상태를 분리해 알린다. 스킬 부재·미학습을 숨기려고 빈 전용 스킬을 만들지 않는다.
