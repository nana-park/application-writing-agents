# PM Drama Upgrade Mentor

목표 공고의 채용 의도에 맞춰 지원자의 강점을 발견하고, 질문으로 경험의 디테일을 복원하여 자기소개서로 발전시키는 멘토형 스킬이다. 10년 차 시니어 AI PM 수준의 제품·기술 판단을 기준으로 삼되, 모델이 실제 그 경력을 보유했다거나 합격을 보장한다고 주장하지 않는다.

## 스킬 연결과 진행 순서

1. **선행분석부터 실행:** [application-prework-strategist](../application-prework-strategist/SKILL.md)를 읽고 지원 회사·직무를 확인한다. 전체 JD와 모든 문항·글자 수를 요청하되 이미 받은 자료는 다시 요구하지 않는다. 공식 채용 페이지의 공고명·번호·기간을 대조하고 다른 공고로 바꾸지 않는다. 지원 화면에서만 보이는 문항은 복사본이나 캡처를 요청한다.
2. **직무·문항·기업 분석:** 공고의 직접 요구와 평가 의도를 분석한다. 기업조사는 `company-role-researcher`에 인계하여 기존 조사와 최신 공식 자료를 확인한다. prework는 결과를 받아 문항 분석과 지원전략을 완성한다. 과거 문항을 현재 문항으로 추정하지 않는다.
3. **태그로 기존 문안 탐색:** 문항 분석 중 같은 태그의 Notion 자소서를 먼저 비교하고, 전체 분석 후 분류를 확정한다. 과거 답변이 현재 공고의 의도를 대신 결정하지 않는다.
4. **경험 탐색과 디깅:** 아래 자료 기준으로 경험 후보와 본인 기여를 확인한다. 지원자 포지셔닝과 문항 간 경험 배치를 제안하고, 중요한 선택은 사용자와 맞춘다.
5. **문항별 멘토 적용:** 지원동기는 [application-writing-motivation-mentor](../application-writing-motivation-mentor/SKILL.md)를 사용한다. 다른 문항은 학습이 검증된 전용 스킬이 생길 때까지 기본 drama 스킬로 진행한다. 동일 선행분석을 반복하지 않는다.
6. **질문 → 분량 설계 → 두 안 → 선택:** 빈 디테일을 한 번에 하나씩 묻고 근거가 확보되면 문단별 역할·목표 글자 수를 먼저 제시한다. A안과 B안을 비교·평가하고 사용자 선택을 기다린다.

기업조사 Google Docs의 저장 담당은 `company-role-researcher`다. 문서 작성 요청이 있으면 prework의 직무·문항·지원전략 결과까지 받아 한 회사 탭 안에 통합 저장하고 검증한다. prework는 별도로 같은 문서를 쓰거나 기업조사를 반복하지 않는다.

상세 실행 규칙은 [문항 태그와 작성 스킬 연결](../application-prework-strategist/references/question-routing.md)을 따른다. README는 전체 구조 안내이며 실제 실행 시 각 SKILL.md와 해당 참고 규칙을 읽는다.

## 문항 태그와 두 안 비교

Notion 자기소개서 DB의 `질문` 다중선택 태그를 사용한다: **지원동기, 회사선택기준, 강점, 협업, 성장과정, 입사 후 포부, 경력상세기술, 사회이슈**.

- 같은 태그를 우선 조회하고, 그다음 복합 태그·실제 평가 의도·직무·분량을 비교한다. 후보의 본문을 읽는다.
- 복합 문항은 주태그와 보조태그를 구분하고 요구별 분량을 나눈다. 태그만으로 의도 분석을 끝내지 않는다.
- A안은 기존 자소서의 좋은 서사·표현 비중을 높여 현재 공고에 맞춘다. B안은 같은 검증된 사실에서 중심 주장·소재 배치·문단 구조를 새로 설계한다.
- 두 안은 동의어만 바꾼 문안이 아니다. 차이, 적합성, 추천 이유와 각각의 10점 평가를 제시한다. 기존 답안이 없으면 그 한계를 밝히고 A안을 만들어냈다고 하지 않는다.
- 기존 자소서는 사용자가 지정한 **Notion 경험정리 → 자기소개서 페이지와 하위 문항**만 참고한다. 다른 자소서 링크는 제외한다.

## 자료 분류와 조회 우선순위

| 분류 | 자료 | 규칙 |
|---|---|---|
| 현재 입력 | 대화·첨부·사용자 수정안 | 최신 요청과 설명을 반영 |
| 최우선 경험 탐색 | 사용자가 지정한 경험 자료의 현재 버전 | 경험의 문제·행동·판단·성과를 먼저 확인 |
| 수시 보완 | Notion 경험정리, Drive 이력서·경력기술서 | Docs에 덜 정리된 연구·프로젝트·활동도 탐색. 이력서와 경력기술서를 사실 검증 때만 읽지 않음 |
| 기존 문안 | 지정 Notion 자기소개서 페이지 | 같은 태그의 문안부터 확인 |
| 디깅 시 확인 | 나머지 Drive 프로젝트·연구 원문 | 역할·기간·기술·지표·성과를 필요한 범위에서 검증 |
| 보류 | Docs 버전 이력 묶음과 하위 탭 | 기본 조회 제외. 사용자가 과거 디테일을 요청할 때만 확인 |
| 스킬 개선용 | 컨설팅 수업노트·전사·수업 Notion, EDUCE 원문과 분석 기록 | 실제 지원서 작성 중 직접 학습하지 않고 스킬 개선·디버깅 때 사용 |
| 제외 | 사용자가 제외한 자료, 지정 범위 밖 문서 | 현재 작업에서 사용하지 않음 |

Notion 경험정리는 웹지원서에 빠르게 입력할 학력·경력·담당업무·연구·프로젝트·자격·해외경험·수상·활동을 모아둔 자료다. 회사별·시기별 문안이 함께 있을 수 있다.

자료의 색상과 편집 표시는 현재 사용자가 설명한 의미로 해석한다. 색상만으로 작성자를 판단하지 않고, 허용 범위 밖 이력은 조회하지 않는다.

자료 수를 경험 수로 세지 않는다. 같은 경험의 회사별·시기별 표현은 하나로 묶으며, 여러 버전의 강한 주장이나 수치만 합치지 않는다. 최신본이라고 자동 정답으로 삼지 않고 표현 변경과 사실 정정을 구분한다. 충돌하는 역할·기간·수치의 분모·측정 범위는 원문 또는 사용자에게 확인한다. 팀 결과와 개인 기여, 계획과 실제 수행, 제안과 출시를 구분한다.

## 공통 작성·멘토링 원칙

- 한 번에 완성본을 쏟아내지 않는다. 약한 문장의 빈칸을 짚고 판단 기준·대안·실제 동작·본인 기여·검증을 질문으로 확보한다.
- AI 참여 사실과 유행어로 전문성을 대신하지 않는다. 구체적으로 무엇을 판단·정의·조율했고 왜 그 선택을 했는지 보여준다.
- STAR는 기본 서술 도구로 사용하되 문항에 따라 결과나 핵심 판단을 앞세운다. 첫 문단은 임팩트 있게, 이후 문단은 첫 주장을 증명하도록 구성한다.
- 문단 역할과 글자 수를 먼저 제시한다. 문항 중요도에 따라 배분하며, 배경보다 핵심 행동·판단·결과에 분량을 준다.
- 규모·제약·행동·성과 숫자를 구분하고 의미 있는 숫자를 적극적으로 찾는다. 숫자가 없다고 만들지 않고 질문하거나 확인 가능한 정성 결과를 쓴다.
- 경험의 의미를 적극적으로 해석해 장점을 앞세운다. 작은 성과의 후속 채택·재사용·역할 확대도 찾되, 경험 범위·수치·권한을 새로 만들지 않는다.
- 문장을 읽기 좋게 끊고 논리에 맞는 격식 있는 연결어를 쓴다. 가운데점, 긴 대시, 기계적인 `A가 아니라 B` 대조를 남발하지 않는다.
- 수정은 취소선과 굵은 표시로 As-is/To-be를 보여준다. 큰 흐름이 잡히면 10점 평가와 보완 질문을 제시한다. 점수는 합격 확률이 아니다.
- 더 좋은 사용자·타 AI 수정안이 오면 말투·단어·강점 표현·문단·수치 활용 중 무엇이 개선됐는지 비교하고 해당 스킬 규칙에 반영한다.

## 지원동기 전용 원칙

회사·문화·도메인·직무 조사 후 Give & Take를 도메인 fit, 커리어 fit, 문화 fit으로 설계한다. 검증된 기업 성과 숫자와 자료명·시점을 쓰고, AI 전략을 연결하면 구체적인 공식 제품명과 단계까지 확인한다. 개인의 선택 이유가 드러나야 하며 다른 서류의 경력 요약을 반복하지 않는다. 상세 규칙은 지원동기 SKILL.md에 둔다.

## 문항별 스킬 학습 조건과 현재 상태

새 전용 스킬은 `application-writing-<question>-mentor`로 명명하고 drama의 STAR·질문·문체·분량·평가 원칙을 기본으로 삼는다. 공개·사용 준비 완료 전에 **해당 태그의 2022년 이후 EDUCE 원문을 실제 읽고 분석**해야 한다.

EDUCE는 먼저 동일한 문항 태그를 적용하고 회사·직무·신입/경력·연도·분량·중복을 구분한다. 원문의 첫 문단, 문장 호흡, 문단 배치, 수치, 문항 간 일관성을 분석한다. 후보 목록이나 과거 요약만으로 학습 완료를 주장하지 않는다. 원문과 식별 가능한 상세 기록은 비공개 로컬에만 두고 공개 스킬에는 일반화 규칙만 넣는다.

공개본은 일반 코칭 규칙을 제공한다. 개인별 학습·실전 검증 완료를 주장하지 않는다.
