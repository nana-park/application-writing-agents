# 증거와 지원서 포트폴리오

이 문서는 AI·데이터 경험의 실제 증거 수준을 판별하거나 여러 문항의 경험을 배치할 때 읽는다. 개별 합격자소서의 문장이나 사례를 재현하지 않는다.

## 문항 오독 방지

초안을 고치기 전에 다음을 구분한다.

1. 문항이 직접 요구한 답
2. 채용자가 이 질문으로 해소하려는 의심
3. JD의 핵심 과업과 기대 결과
4. 회사·제품에만 해당하는 문제
5. 전체 지원서에서 이 문항이 새로 증명할 역할

예를 들어 AI 강점을 묻는다면 `AI 서비스를 했다`가 답이 아니다. 어떤 AI 능력을 어떤 제품 문제에 썼고, 모델 한계 때문에 무엇을 판단했으며, 어떻게 검증·운영했는지가 증거다.

## AI·데이터 증거 단계

| 단계 | 확인되는 내용 | 주장 가능한 범위 |
|---:|---|---|
| 0 | 관심, 산업 전망, 기술 용어 | 지원 동기 |
| 1 | 수업·교육에서 도구나 모델 사용 | 기초 학습 경험 |
| 2 | 입력·처리·출력이 있는 산출물 | 기술 프로젝트 수행 |
| 3 | 기준선·지표·오류 유형·반복 실험 | 기술적 개선과 검증 |
| 4 | 사용자 흐름·정책·운영 결정과 연결 | AI·데이터 제품 적용 |
| 5 | 배포·반복 사용과 제품·운영 성과 | 실서비스 운영 성과 |

상위 단계의 용어를 썼다는 이유로 경험 수준을 올리지 않는다. 현재 확인된 가장 높은 단계부터 시작해 목표 JD에 필요한 다음 고리만 질문한다.

## AI PM 경험의 일곱 고리

1. 누구의 어떤 판단·행동이 어려웠는가?
2. 입력 데이터의 출처·품질·권한·갱신 제약은 무엇인가?
3. 모델은 예측·분류·검색·생성 중 무엇을 맡았고 기존 방식은 무엇인가?
4. 어떤 지표와 실패 유형으로 쓸 만한지를 판정했는가?
5. 출력은 어느 화면·정책·API·운영자 행동으로 이어졌는가?
6. 품질·지연·비용·안전·개인정보·운영 부담 중 무엇을 선택했는가?
7. 모델 점수와 별도로 사용자·업무·제품 결과가 어떻게 달라졌는가?

모든 고리를 한꺼번에 캐묻지 않는다. 현재 주장을 무너뜨리는 가장 큰 빈칸 하나를 골라 묻는다.

## 경험 선택

경험의 이름과 화려함보다 목표 과업과 행동 구조가 같은지를 본다. 기술명이 많은 수업보다 반복 제어·오류 진단·사용자 흐름을 실제로 바꾼 작은 경험이 더 강할 수 있다.

후보 경험은 다음을 0~2점으로 비교한다.

- JD 과업과의 근접성
- 판단·대안 선택의 밀도
- 본인 책임과 산출물의 선명도
- 결과·후속 사용의 검증 가능성
- 질문으로 디테일을 복원할 가능성
- 문항의 숨은 평가와의 적합성

좋은 경험도 다른 문항과 같은 캐릭터·결론을 반복하거나, 본인 기여를 분리할 수 없거나, 숫자의 기준을 방어할 수 없으면 교체한다.

## 경험을 크게 만드는 합법적인 방법

- 작은 수치의 맥락과 제약을 밝혀 결정의 난도를 살린다.
- 단발 결과 뒤의 재사용·후속 채택·정책 반영·교육·운영 체계를 찾는다.
- 단순 요청 뒤에서 상대가 실행할 수 있도록 만든 자료·권한·일정·범위 조정을 찾는다.
- 분석 뒤 바뀐 문제 정의·기준·우선순위·자원·형식을 밝힌다.
- 같은 프로젝트를 문제정의·제품 판단·협업·실패 수정의 서로 다른 장면으로 나눈다.

하지 않은 구현·승인·배포를 했다고 쓰거나, 팀 전체 성과를 개인 성과로 바꾸거나, 없던 갈등·수치·대사를 추가하지 않는다.

## 숫자의 층위

- 교육시간·학습일수·과제 수: 노력량
- 처리 건수·사용자 수·실험 횟수: 범위
- 정확도·지연시간·오류율: 기술 결과
- 전환율·과업 완료율·처리시간·문의 변화: 제품·운영 결과
- 매출·비용·계약·후속 사업: 사업 결과

숫자의 대상·기간·분모·기준선·산식과 본인의 기여를 확인한다. 숫자가 없으면 후속 사용이나 조직에 남은 자산을 찾되 없는 결과를 만들지 않는다.

## 여러 문항의 배치

먼저 지원자를 한 문장으로 기억하게 할 행동 원리를 정한다. 각 문항은 같은 문구를 반복하지 않고 다른 증거를 제공한다.

| 문항 | 주로 맡길 증명 |
|---|---|
| 지원동기·포부 | 회사의 구체 과제와 자신의 방향·재현 행동 |
| 직무역량 | 가장 강한 산출물·판단·책임·결과 |
| 문제해결 | 표면 문제를 다시 정의하고 선택을 바꾼 과정 |
| 협업 | 상대의 제약을 수용 가능한 실행 조건으로 바꾼 과정 |
| 실패·성장 | 최초 판단의 오류와 후속 재적용 |
| 가치관·자유소개 | 기억 가능한 인간적 캐릭터와 실제 선택 |
| 산업·제품 제안 | 사용자·데이터·회사 자산·실행 제약·성공 지표 |

전체 문항의 첫 문장과 소제목만 이어 읽어도 같은 사람으로 보이는지 확인한다. 첫 문항의 겸손 표현이 뒤 문항의 책임·성과와 모순되지 않아야 한다.

## AI 제품 제안 검사

AI를 붙인 제안에는 다음을 확인한다.

- 입력 데이터는 어디서 얻고 사용자는 활용에 동의하는가?
- 결과가 틀렸을 때 누가 수정·거부·우회할 수 있는가?
- 기존 방식보다 좋아졌다고 볼 제품·운영 지표는 무엇인가?
- 현장 업무, 비용, 지연, 개인정보·안전 위험은 감당 가능한가?
- 회사가 가진 채널·데이터·파트너를 어떻게 쓰기 때문에 실행 가능한가?

이 질문에 답이 없으면 AI 제안은 아이디어 수준으로 표시하고 핵심 전문성 증거로 쓰지 않는다.
