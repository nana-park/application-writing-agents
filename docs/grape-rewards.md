# 포도알 칭찬 운영

메인 PL은 팀의 칭찬판을 관리한다. 직속·중첩 깊이·업무 종류와 무관하게 모든 에이전트가 개인 판을 받을 자격이 있다. 이 규칙 자체가 새로운 하위 에이전트 생성 권한을 확대하지는 않는다.

## 생성과 저장

- 에이전트가 처음 추가되면 안정적인 agent_key와 표시 이름, 역할, 부모 키를 등록한다. 같은 에이전트의 후속 실행에서는 기존 판을 재사용하고 다른 에이전트끼리 판을 공유하지 않는다.
- `private/main-agent/grapes/<agent_key>/` 아래 개인 판 이미지와 `rewards.json`을 보관한다. 개인정보·작업 원문은 넣지 않으며 Git에 올리지 않는다.
- 개인 판을 사용하는 경우 사용자가 선택한 디자인과 칸 수를 확인한다. 실제 기여 기록은 Git 제외 위치에 둔다.
- 판에는 고정 시간 내 완료를 수상 조건으로 넣지 않는다.
- 이미지 생성이 급한 자소서 작성을 지연시키지 않도록 에이전트 등록 시 pending 상태를 남기고, 독립적인 작업 대기 구간이나 제출 후에 제작한다. 이미지 대기 중에도 원장 기록은 유지한다. 미생성 판을 생성 완료라고 하지 않는다.

## 수여

세부 수여 기준을 사용자와 추가로 마련하기 전까지 메인 재량으로 수여한다. 아래 좋은 기여 항목은 예시이며 고정 점수표나 자격 조건이 아니다. 수여 날짜·시각과 이유 기록은 유지한다.

- 사용자의 매번 승인을 기다리지 않고 메인이 각 에이전트의 잘 수행한 일을 검수한 뒤 1알씩 수여한다. 사용자에게만 수여권이 있다는 이전 시안 문구는 적용하지 않는다.
- 평가 근거는 좋은 조사 근거, 적합한 소재 발견, 정확한 검증, 설득력 있는 문장, 효율적인 수정, 유용한 협업 등 구체적인 수행이다. 빠르기만 하거나 무조건 동의하는 행동, 미확인 사실 은폐에 보상하지 않는다.
- 동일 작업·동일 기여를 중복 수여하지 않는다. 소요 시간만으로 다른 에이전트의 좋은 기여를 무시하지 않는다. 스티커는 품질 검수나 사실 확인을 대체하지 않는다.
- 수여 시 실제 현재 시각을 확인하여 `awarded_at`에 Asia/Seoul 오프셋이 있는 ISO 8601 시각을 기록한다. 작업 키, 수여 이유, 검수 근거 요약, 수여자 main, 회차, 포도알 번호도 기록한다. 비공개 지원서 내용을 이유에 복사하지 않는다.
- 원장이 기준이며 이미지에는 포도알 채움 상태와 수여 기록 표(번호·날짜/시각·짧은 이유)를 맞춘다. 여러 건의 그림 갱신은 묶어서 처리할 수 있지만 미반영 상태를 구분한다. 원장 없이 이미지 색만 채우지 않는다.

## 완판

20알이 모두 수여되고 이미지와 원장이 일치하면 해당 에이전트가 메인을 통해 한 번 당당히 말할 수 있다: `에이전트 <이름>입니다. 칭찬해주십쇼!`

완판 기록은 보존한다. 이후 새 회차의 빈 판을 만들어 이어가며 기존 기록을 지우거나 자동으로 새 판에 스티커를 이월하지 않는다.

원장 최소 필드: agent_key, display_name, parent_agent_key, round, capacity(20), board_status(pending/ready/update_pending), awards[{award_id, task_key, grape_number, awarded_at, awarded_by, reason, review_evidence}], celebration_announced_at.
