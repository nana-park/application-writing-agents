# 자기소개서 초안 Notion 저장

기업조사 보고서는 researcher → Google Docs, 자기소개서 초안은 main → Notion으로 분리한다. Writer는 본문을 반환하고 메인이 단일 저장 담당자가 된다. 기존 저장 요청과 확인된 대상은 이어서 사용하며 매번 재승인을 받지 않는다. 사용자가 채팅에서만 작업하도록 지정하면 외부 저장하지 않는다.

1. 작성 시작 시 현재 지원 건의 Notion 대상 페이지를 확인한다. 기존 비공개 소스 설정과 현재 대화에서 지정한 자기소개서 위치를 읽고 실제 회사·직무·문항을 대조한다. 과거 답안 조회용 페이지를 새 초안의 저장 대상으로 자동 간주하지 않는다. 대상이 없거나 여러 곳이면 작성은 계속하고 메인이 위치만 질문한다. URL이나 페이지 ID를 추측하지 않는다.
2. 처음 완성된 A/B를 사용자에게 제시하는 단계에서 둘 다 `초안·검수 전`으로 저장한다. 최종안 선택을 저장의 선행 조건으로 두지 않는다. 회사·직무·문항 원문·글자 수 제한·A/B 구분·버전·작성 시각·본문·사실 확인 항목을 포함한다. 확인되지 않은 해석은 본문과 구분하고 제출본으로 표시하지 않는다.
3. Notion 도구 사용 전 해당 연결 스킬을 읽고 페이지 구조와 속성을 확인한다. 기존 답안과 사용자 수정은 보존한다. 회사·직무·문항·버전으로 중복을 확인하고, 이번에 생성한 초안 구역만 수정한다. 같은 페이지에 Writer나 reviewer가 동시에 쓰지 않는다.
4. 저장 후 대상 블록을 다시 읽어 A/B 본문 전체, 문항, 버전, 소제목과 빈 줄, 누락·잘림 여부를 확인한다. 링크와 저장 상태를 사용자에게 반환한다. 도구 성공 응답만으로 본문 저장 완료를 선언하지 않는다.
5. 리뷰를 반영한 버전과 사용자 선택본은 별도 버전·상태로 기록한다. 사용자 확정 전에는 최종 제출본으로 승격하지 않는다. 확인되지 않은 사실은 계속 표시한다.
6. 실패하면 작성 완료와 저장 실패를 구분해 보고하고, 원문을 Git 제외 private/에 보존한다. 권한·대상 누락·도구 오류·재조회 불일치를 구분한다. timeout 후에는 먼저 실제 저장 여부를 조회하여 중복 생성을 막는다. 저장 장애 때문에 초안 제시를 늦추지 않고 미저장 항목과 필요한 조치만 알린다.

완료 보고는 `작성 상태 / 검수 상태 / Notion 저장 상태 / 확인한 페이지 링크·버전`을 구분한다. 이 지침 추가나 Git 배포는 실제 Notion 저장 성공을 의미하지 않는다.

최신 검토 A/B와 선택 상태를 페이지 상단에서 찾을 수 있게 한다. 사용자 원문은 보존하고 이전 버전은 내용 손실 없이 접힌 히스토리로 구분한다. 글자 수 속성은 어느 안·버전 기준인지 명시하며 미선택 A/B를 단일 확정값으로 표시하지 않는다. 기존 사용자 속성은 의미를 확인한 뒤 갱신한다. 보고서의 초안 버전 참조도 최신 전략과 일치시키되 조사 기준일과 작성 버전은 구분한다.
