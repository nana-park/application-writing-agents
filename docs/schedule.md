# 호출 조건과 병렬 실행

## 시간 예산 — 보고서 8분 / writing 검수 포함 5분

보고서 조사·분석·정리·저장 확인은 research-report-contract.md의 총 8분 제한을 유지한다. 보고서 목차와 AI 조사 항목은 변경하지 않는다.

Writing은 문항당 총 5분 상한이다. 기존 자료 확인·필요한 인계, 작성, 독립 리뷰, 수정, 수정 후 필수 재검수, 요청된 저장·확인을 모두 포함한다. 작성만 5분이나 역할별 5분이 아니다. A/B가 필요한 경우 두 안을 합친 예산이다. 사람의 답변·검토 대기는 별도로 기록하고 AI 작업 시간에서 제외한다.

Main은 writing 착수 시 시작과 5분 뒤 마감 시각을 모든 담당자에게 전달한다. 참고 배분은 작성·인계 2분, 초회 병렬 리뷰 1분, 수정 1분, 변경부분 재검수·저장 1분이다. 수정량에 맞게 조절하되 총 5분은 늘리지 않는다. 인계·재시도·후속 호출로 시계를 초기화하지 않는다. 호출 전후와 단계 전환 시 실제 시간을 확인하고 대기는 남은 시간 이하로 제한한다.

기존 문항 재작성·문장 수정은 기존 조사·전략·근거·초안을 재사용하고 `요청 범위 확인 → 해당 구간 수정 → 변경부분 필수 재검수 → 요청된 저장`만 수행한다. 변경된 JD나 새 사실이 없는 한 기업조사, 경험 전수 탐색, 사례 재검색, 전체 문항 설계를 다시 돌리지 않는다. 사용자가 한 안의 수정을 요청하면 새 A/B를 강제로 만들지 않는다.

수정사항이 있으면 수정 주체·크기와 무관하게 담당 독립 리뷰어가 변경 부분을 반드시 재검수한다. 양쪽 평가에 영향이 있으면 병렬로 확인한다. 시간 부족을 이유로 재검수를 생략하거나 통과하지 않은 버전을 완료로 표시하지 않는다. 5분에 미완료면 확보된 문안과 검수 대기·미해결 사실·저장 상태를 반환하고 자동 연장하지 않는다. 중단할 수 없는 외부 도구 지연은 실제 초과 시간과 함께 알리며, 지침만으로 실행시간을 보장한다고 주장하지 않는다. 저장 실패는 문안 전달을 막지 않는다.

### 최소 작성 조건

조사 → 전략·경험 → 작성 → 리뷰 순서는 유지한다. 조사 중 기존 답안·경험·사례 탐색은 병렬로 가능하며 유효한 기존 조사·전략은 재사용한다.

- Researcher는 8분에 부분 조사라도 반환한다. 모든 목차를 유지하되 미조사·미공개·접근 불가를 구분한다. 비핵심 미조사와 Docs 저장 장애는 작성 차단 사유가 아니다.
- Prework와 Main은 확인된 회사 근거·JD로 회사 과제, 지원 이유, 포지셔닝, 문항별 소재와 분량을 정한다. Evidence는 해당 주장에 필요한 역할·수치만 확인한다. 별도 승인 라운드를 추가하지 않는다.
- research_version·strategy_version·evidence_version과 writing-brief에 확인된 사실 및 미확인 범위를 함께 담는다. Coordinator는 비핵심 누락을 이유로 반송하지 않고 가능한 범위의 A/B를 작성한다.
- 핵심 경험·수치가 없으면 그 주장만 제외하거나 확인 표시한 제안으로 분리한다. 사실을 창작하지 않는다. JD나 문항 자체가 없으면 사용자에게 요청하고 확인 가능한 부분 결과를 먼저 반환한다.

| 단계 | 호출 조건 | 담당 | 병렬 허용 | 통과 조건 |
|---|---|---|---|---|
| 입력 | 작성 요청 | main | 없음 | 회사·직무·공고·전체 문항과 제한 확보, 또는 구체적 누락 요청 |
| 초기분석 | 대상 JD 확보 | prework / researcher | 서로 병렬 | prework의 잠정 의도·태그·기존 답안, researcher의 공식 인재상·최신 공개 IR 포함 기업 근거 반환 |
| 분석 통합 | 기업조사 반환 | prework 후속 | 회사와 독립적인 소스 위치 확인만 병렬 가능 | 회사 맥락 반영한 의도·태그 확정 |
| 경험 디깅 | 의도·태그·기존 답안 확인 | evidence | 기본 순차 | 역할·수치·중복 버전 확인, 빈 디테일 반환 |
| 질문·설계 | 사실 충돌이나 방향 선택 필요 | main, 필요 시 prework 후속 | 확인된 부분은 진행, 미확인 주장만 보류 | 공통 사실 버전·주장·문항 배치·분량 확정 |
| 작성 | 작성 시작 조건 통과, 동일 조사·전략·근거 버전과 분량 전달 | writer-coordinator → 전용 에이전트 또는 범용 A/B | 조건 통과 후 범용 A/B 병렬 | A/B 초안·사용 근거·글자 수·불확실성 반환 |
| 독립 리뷰 | 두 안과 공통 근거 반환 | reviewer-it-hr / reviewer-it-service-planning | 두 리뷰어와 메인의 전략 검수 병렬 | 동일 버전의 A/B별 결함·근거·추천 반환 |
| 검수·선택 | 리뷰 반환 | main | 없음 | 중복·상충 의견 조정, 최종 점수·수정 지시·사용자 선택 |
| 초안 저장 | A/B 작성 완료 및 Notion 대상 확인 | main | 리뷰와 병행 가능, 동일 페이지 동시 쓰기 금지 | docs/draft-storage.md에 따라 검수 전 초안 저장·본문 재조회·링크 반환. 최종 선택까지 미루지 않음 |
| 보고서 저장 | 분석 통합 완료, 기존 저장 요청·대상 확인 | researcher 후속 | 경험 디깅과 병행 가능, 동일 문서 동시 쓰기 금지 | Google Docs 재조회 검증과 문서·회사 탭 링크 반환. 자소서 최종 선택을 기다리지 않음 |

현재 런타임은 메인 포함 4슬롯이므로 자식 최대 3개다. 모든 역할을 상시 생성하지 않는다. 리뷰 시작 전 작성 에이전트의 점유 상태와 슬롯 확보 가능 여부를 확인한다. 완료됐다고 슬롯이 자동 해제된다고 가정하지 않는다. 가능한 도구로 슬롯을 확보하고 불가능하면 순차 검토로 전환해 제한을 알린다. 작성자를 그대로 자기 결과의 독립 리뷰어로 사용하지 않는다. 리뷰는 메인 전략 검수와 병행하며 필수 기준 충족 여부로 완료를 판단한다.

재작업은 변경 범위로 제한한다. 문장 교정은 writer-coordinator만, 숫자 충돌은 evidence 확인 후 영향 문단 writer-coordinator만, JD 변경은 prework 및 관련 기업조사부터 재개한다. 기존 유효한 결과를 재사용한다. 수정 후 담당 리뷰어의 변경부분 재검수까지 완료해야 검수 완료다. 목표 시간에 재검수가 끝나지 않았다면 마지막 수정본을 검수 대기 초안으로 반환하고 제출 가능·최종 검수 완료로 표시하지 않는다. 시간 초과를 숨기거나 자동 연장하지 않는다. 도구 실패나 사용자 대기 상태를 완료로 처리하지 않는다.

JD의 다른 항목으로 경험을 재해석할 여지가 있으면 예외적으로 `writer-coordinator 제안 초안 → main이 사용자에게 초안과 사실 확인 질문 제시 → 확인 후 사실 버전 갱신 → 영향 문단 재검수` 순서로 진행한다. 확인 전 제안은 제출 가능 초안과 분리한다. 제안을 만들기 전 모든 질문을 끝내도록 강제하지 않는다.

작성 경로는 agents/writer-coordinator.md를 따른다. 전용 에이전트도 A/B 두 안을 반환한다. registry의 학습 미검증 역할은 자동 전용 경로로 활성화하지 않는다.
