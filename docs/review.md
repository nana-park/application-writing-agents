# PL 검수 기준 v1

이는 초기 운영 기준이며 실전 결과에 따라 개선한다. 전문적인 문체와 문항별 내용 평가는 drama 및 해당 writing 스킬을 참조한다.

## 통과 전 필수 점검

- 문단별 역할이 구분되고 하나의 중심 주장에 기여하는가? 인접 문단의 끝문장과 첫문장 사이에 주제 급전환·숨은 전제·반복이 없는가? 도입을 본문이 입증하고 결말의 기여 방향이 경험과 회사 선택 근거에서 도출되는가? 결함은 해당 문단 쌍과 누락된 연결 근거, 이동·통합·삭제·보강 중 필요한 수정으로 반환한다. STAR 충족이나 JD 단어 포함만으로 통과시키지 않는다. 수정본은 인접 문단까지 다시 검토하며 별도 리뷰 사이클은 추가하지 않는다.

- 경험 구간에서 프로젝트와 본인 역할 → 문제의 기준 수치 → 판단·해결 행동 → 결과의 수치 변화가 연결되는가? 확인된 숫자가 누락되거나 행동이 추상어로 대체되지 않았는가? 정량 근거가 없으면 확인 가능한 구체 변화로 설명했는가?
- 지원동기·직무역량·기여 문항은 과거 해결 방식이 JD의 어떤 업무에 어떻게 적용돼 어떤 성과에 기여할지 연결되는가? 과거 수치를 미래 성과 보장으로 복사하지 않았는가? 구체 작성 기준은 drama 스킬의 STAR와 지원 업무 연결 절을 따른다.

- 현재 공고·문항·글자 수가 맞는가? 복합 문항의 요구를 빠뜨리지 않았는가?
- A/B가 동일한 확정 사실 버전을 사용하는가? 사실·제안·멘토 피드백이 섞이지 않았는가?
- 역할·성과·기간·분모에 미해결 충돌이나 근거 없는 추가가 있는가?
- 기업 수치·제품명·자료 시점에 추적 가능한 출처가 있는가?
- 글자 수를 실제로 계산했는가? 제목·공백 포함 기준과 초과 여부가 명확한가?
- 다른 문항과 중복되거나 상충하지 않는가? 두 안이 실질적으로 다른가?
- JD의 중요한 표현이 문항의 목적과 경험에 맞게 분산되어 있는가? 같은 단어의 불필요한 반복, 정확한 JD 표현으로 치환 가능한 부분, 다른 JD 항목으로 재해석할 여지를 아래 기준으로 점검했는가?
- 비공개 내용의 공개 범위와 저장 요청을 준수하는가?

사실 충돌·문항 누락·분량 초과는 총점이 높아도 제출 가능으로 표시하지 않는다. 해당 부분을 담당자에게 돌려 수정한다. 미해결 항목은 사용자에게 드러낸다.

## 공통 10점 평가

문항 적합성 2, 강점·포지셔닝 2, 디테일·판단·근거 2, 전개·가독성 2, 회사 적합성·전체 지원서 일관성 2로 평가한다. 문항별 세부 진단은 전용 스킬 기준을 연결하되 서로 다른 총점을 혼합하지 않는다. 모든 항목에 점수와 문장 근거, 가장 중요한 개선점을 제시한다. 임의의 합격 확률로 번역하지 않는다.

서브의 자기평가만 복사하지 않고 PL이 원문·인계 사실과 대조한다. A/B 각각 평가하고 추천 이유와 남은 결함을 제시한 뒤 사용자 선택을 받는다. 선택 후 수정된 본문도 재검수한다.

수정 요청 형식: 문제 문장 또는 항목 / 실패 기준 / 근거 / 수정 목표 / 변경 금지 사실 / 완료 확인 방법. 전면 재작성은 실제 문항 해석이나 중심 주장이 바뀐 경우에만 지시한다.

## JD 표현과 경험 관점 검수

1. 현재 JD의 주요 업무·필수·우대에서 중요한 명사뿐 아니라 행동 동사, 산출물, 책임과 평가 대상을 추린다. 각 표현의 JD 원문 위치와 의미를 확인한다. 모든 단어를 넣는 것을 목표로 하지 않는다.
2. 문항별로 `JD 표현 / 해당 문장·경험 / 사용 횟수 / 누락·반복·치환·재해석 여부`를 비교한다. 한 문항 안과 전체 지원서에서 같은 단어를 불필요하게 반복하지 않고, 서로 다른 핵심 항목을 경험과 문항 의도에 맞게 고르게 드러낸다. 정확한 제품·기술 명칭의 필요한 반복은 허용하며 억지 동의어로 의미를 흐리지 않는다. 균등 횟수나 키워드 밀도 목표를 만들지 않는다.
3. 일반적 표현을 JD의 정확한 표현으로 바꿀 여지가 남았는지 점검한다. 예: 단순히 '정리'라고 썼지만 실제 행동이 요구사항 정의인지, 운영 기준 수립인지 확인한다. 의미가 같은 단어 교체와 역할·범위가 달라지는 재해석을 구분한다. 표현만 나열하거나 경험에 없는 기술·성과·권한을 붙이지 않는다.
4. 같은 경험이 JD의 다른 항목을 증명할 수 있는지도 검토한다. 새 관점으로 쓰고 싶으면 질문만 먼저 던지지 말고 writer-coordinator에게 **사실 확인 전 재해석 초안**을 먼저 작성하게 한다. 메인은 `기존 표현 → JD에 맞춘 초안 → 새로 해석한 부분 → 사실 확인 질문` 순서로 사용자에게 보여준다. 특히 무엇을 판단·정의·관리했다고 읽히는지 구체적으로 묻는다. 사용자 대신 답하지 않는다.
5. 이 초안은 제안 단계의 예외로, 확정 사실 묶음에 넣거나 제출본·확정 보고서에 반영하기 전에 사용자 확인을 받는다. 이미 확인된 수치·역할은 유지하고 빈 사실을 창작하지 않는다. 확인되면 사실 버전을 갱신하고 관련 문항을 재검수한다. 부정되면 해당 해석을 수정·철회한다.

사용자에게는 키워드 개수만 보고하지 않는다. 실제로 남은 반복, 치환 후보와 새 관점 후보를 문장 단위로 제시한다. 새 관점의 근거가 없거나 현재 문항과 무관하면 제외한다. JD 표현의 적합성은 기존 '문항 적합성' 및 '회사 적합성·전체 지원서 일관성' 점수에 반영하며 총점을 추가하지 않는다.

## 유지하는 운영 규칙

보고서 조사·저장 계약과 수정 후 필수 독립 재검수는 유지한다. Writing 시간은 문항당 작성·수정·독립 검수·재검수·요청된 저장을 합친 총 5분 제한로 정한다. 이는 시간을 채우라는 뜻이 아니다.

초회 리뷰는 기존 HR·서비스기획 리뷰어가 병렬로 수행한다. 누구의 수정이든 변경사항이 있으면 담당 독립 리뷰어가 해당 버전의 변경 부분을 반드시 재검수한다. 메인 점검만으로 대체하지 않는다. 시간 내 완료하지 못하면 검수 대기 상태를 명시한다.

## 소제목 검수

- HR 리뷰어는 제목만 읽어도 무엇을 말하고 어떻게 일한 사람인지 예상되는지 확인한다. 추상적인 역량명보다 본문의 행동·판단·전환·결과를 예고하는지 본다.
- 제목이 본문보다 강한 성과나 인과를 주장하지 않는지, 문항별 제목이 구분되는지, 수치가 실제 근거·기간·범위와 맞는지 확인한다. 수치형을 무조건 우선하지 않는다.
- 기본 제출 형식은 `[소제목]` 한 줄 뒤 빈 줄 하나와 본문이다. 별도 제출 규격이 있으면 그 규격을 따른다. 대괄호·제목 및 제출처 기준의 줄바꿈을 글자 수에 반영한다.
- 본문 수정 후 소제목도 다시 대조한다. 제목을 수정했으면 기존 수정 후 필수 재검수 절차에 포함한다. 별도 검수 라운드를 추가하지 않는다.
