# 작업 요구 대응표 템플릿

아래 항목은 일반 점검 예시다. 현재 사용자의 실제 요청과 권한에 맞춰 적용하고 개인별 결과는 비공개 작업 기록에 둔다.

| ID | 사용자 요구 | 기준 위치 | 확인할 적용 증거 |
|---|---|---|---|
| U01 | 지원 대상·JD·전체 문항을 먼저 확인 | main, roles | 원문·제한과 문항 의도 |
| U02 | 회사 심층 조사, 예시의 전체 항목, 보고서 8분 제한, writing 문항당 작성·수정·검수·재검수·저장 총 5분 제한 | research-report-contract | 완전성 표·원출처·비교·해석 |
| U03 | 멘토식 판단, 디테일은 필요한 질문으로 보강 | drama references, evidence | 구체 행동·선택 이유, 핵심 질문 |
| U04 | 강점이 드러나는 경험 해석과 표현 | drama, learned-writing-patterns | 실제 역할을 유지한 강점과 장면 |
| U05 | 지원동기 Give & Take, 도메인·커리어·문화 fit | motivation skill, writer-motivation | 개인 동기·회사 선택·기여의 연결 |
| U06 | 기업 성과 숫자·출처·구체 AI 제품명 | motivation skill, handoff | 수치 정의·출처 원장·본문 반영 |
| U07 | 문단 역할·글자 수 먼저 설계 | writing-brief | 문단별 배정과 실제 제목 포함 분량 |
| U08 | 짧고 읽기 쉬운 문장, 적절한 연결어, 가운데점·대시 자제 | learned-writing-patterns | 문장별 판단 단위와 전환 |
| U09 | 소제목과 빈 줄, 행동·판단·결과가 드러나는 제목 | writer-coordinator, review | 제출용 제목·본문 일치 |
| U10 | 같은 태그의 기존 답안 활용 A와 새 논리 B | writing-brief, specialists | 순서 변경을 넘는 주장·기여 논리 차이 |

| U12 | JD 표현 분산·치환·새 관점은 초안 후 사실 확인 | review, handoff | JD 배치표·본문·확인 질문 |
| U13 | 사용자 선호 표현과 다른 AI의 좋은 안을 보존·반영 | writing-brief, drama | 살릴 요소와 변경 이유 |

프롬프트 간 충돌은 최신 사용자 요청을 우선한다. 본문 괄호 출처 생략은 근거 원장 삭제가 아니고, 미확인은 부재가 아니다. 합성 예시는 사용자 경험이나 합격 원문으로 승격하지 않는다.
