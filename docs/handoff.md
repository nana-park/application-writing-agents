# 인계 계약

Writer에게는 docs/writing-brief.md의 간단한 인계를 적용한다. 기존 문안·검증된 사실·조사 결과와 분량 계획을 두 리뷰어에게도 동일하게 전달한다. 새 사례 재검색과 요구 ID별 설계를 추가 선행 단계로 강제하지 않는다.

리뷰 인계는 docs/review.md의 두 리뷰어 공통 계약을 따른다. Main은 동일 버전의 입력을 두 리뷰어에게 각각 전달하고 역할별 진단을 모두 수신한다. 리뷰 의견과 확정 사실을 섞지 않으며 최종 수정 지시와 점수는 Main이 통합한다.

## 메인의 전체 결과 수신

우대역량 매칭표는 `우대사항 원문·위치 / 핵심 역량 / 연결 경험 ID·문장 / 본인 행동·결과와 출처 / 확인 상태(증명 가능·보완 필요·현재 근거 없음) / 강조할 관점 / 반영 문항·문단`을 포함한다. prework의 잠정 매칭과 evidence의 확인 결과를 구분한다. 같은 경험이 여러 역량을 뒷받침해도 별개 경험으로 중복 계산하지 않는다. Writer와 Main까지 표를 유지하고, 미반영 항목은 문항 무관·분량·근거 부족 등 이유를 남긴다.

prework의 모든 최종 작업물은 main PL이 받는다. evidence에 전달했다고 메인 전달을 생략하지 않는다. 보고서, 전체 문항 정보, 태그·평가 의도, 기존 자소서 기반 가안과 참고 원문, 후킹 후보, 경험 탐색 과제, 변경 해석·확인사항, 전체 문항 배치·분량을 동일 버전으로 main과 evidence에 전달한다. 전체 원문의 매번 복사는 불필요하지만 누락 없이 접근 가능한 위치와 핵심 요약을 제공한다.

문항별 question_id, 문항 원문, 제한 글자 수와 계산 기준, 대상 회사·직무·JD 버전을 모든 downstream 인계에 유지한다. evidence는 이 문항 맥락을 main에 반환하고, main은 writer-coordinator를 통해 A/B 작성자에게 같은 버전을 전달한다.

보고서는 researcher가 실제 저장·readback을 마쳤을 때만 Google Docs 문서·회사 탭 링크와 확인 시각을 제공한다. 저장 전에는 미저장 상태와 현재 조사 패키지를 전달하여 evidence 작업을 막지 않는다. 링크는 전체 보고서 본문을 대체할 수 있지만 핵심 결론·미확인 사항·수치 요약을 대체하지 않는다. 링크 접근 실패 시 내용을 읽었다고 하지 않고 인계문 또는 허용된 작업 파일로 보완한다.

evidence의 필수 반환 항목은 문항별 숫자 후보 표다: 지표명 / 값·단위 / 전후 기준선 / 대상·기간·분모 / 규모·제약·행동·성과 구분 / 본인 기여 / 출처 위치 / 확인 상태 / 추천 문단. 있는 숫자를 빠뜨리지 않되 해당 문항에 필요한 대표 수치를 추천한다. 계산값은 산식과 원자료를 연결한다. 수치가 없거나 충돌하면 그 상태를 명시하고 작성 가능한 대안을 함께 반환한다. main은 숫자 후보 표를 누락한 결과를 완료 인계로 처리하지 않는다.

각 작업은 아래 정보를 텍스트 또는 비공개 작업 파일로 받는다.

- task: 역할, 질문 ID, 입력 버전, 해야 할 일, 완료 조건
- target: 회사·직무·공고 식별정보·확인일, 전체 JD와 문항·글자 수 또는 허용된 소스 위치
- analysis: 직접 요구, 평가 의도와 근거 및 구분(회사 명시 / 문항에서 추론 / 기업조사로 보강), 핵심 단어별 증명 질문과 대응 근거·공백, 주태그·보조태그, 회사 사실/해석/가설
- evidence: 경험 ID, 사실 버전, 본인 역할·행동·지표·범위, 원문 위치, 사용자 추가 설명, 충돌·미확인 사항
- prior_answers: 지정 Notion 답안의 태그, 사용 가능 부분, 기업별로 바꿔야 할 내용
- plan: 문항별 주장·경험 배치(경험 ID별 주요 사례 / 짧게 참조 / 사용하지 않음, 주 배치 문항, 재사용 시 새 관점·정보), 문단 역할과 목표 글자 수, 문체 규칙
- permissions: 읽기 범위, 로컬 출력 위치, 외부 저장 가능 여부
- culture: 인재상·문화의 공식 표현과 출처 / 기대 행동에 대한 해석 / 연결 경험 ID·확인된 행동 / 반영 문항·본문 위치 / 근거 공백. Researcher의 공식 근거와 Prework의 해석, Evidence의 확인을 구분해 Writer·리뷰어까지 전달한다. 회사 문구의 사용 횟수를 목표로 삼지 않는다.

반환은 상태(done/needs-input/blocked), 실제 확인한 소스, 결과, 사실과 제안의 구분, 미확인 내용, 메인이 물어볼 질문, 쓴 파일·외부 변경 여부를 포함한다. done은 해당 하위 작업 완료이며 지원서 전체 완료가 아니다.

태그는 Notion `질문`: 지원동기, 회사선택기준, 강점, 협업, 성장과정, 입사 후 포부, 경력상세기술, 사회이슈. 복합 문항은 다중 분류한다. 같은 태그라도 현재 평가 의도와 다른 답안은 그대로 쓰지 않는다.

A/B 작성자는 동일 evidence_version을 받아야 한다. 충돌하는 지표를 각자 선택하거나, 없는 숫자·갈등·역할을 생성하지 않는다. 최종 검수는 사실 버전 일치, 실제 글자 수(공백·제목 기준 명시), 질문에 대한 직접 답, 현재 회사 고유성, 문항 간 중복, 의미 있는 A/B 차이를 확인한다.
