# 메인 PL 실행 QA

기업조사에는 `AI 히스토리와 전략` 및 `회사와 포지션의 과제`의 실질 내용과 출처가 있어야 한다. 제품명 나열에 그치지 않고 단계, 사업·고객 경험 역할, 강점·한계, 공식 계획과 구분된 2~3년 전망, 경쟁사 비교 및 JD에 연결한 입사자 과제를 확인한다. 미확인은 부족함이나 부재로 단정하지 않는다.

조사 품질은 research-report-contract.md의 모든 필수 절과 출처·완전성 표를 대조한다. 저장 성공만으로 조사 완료를 판정하지 않는다. 사용자 요구 → 조사 → 문항 배치 → 실제 본문 → 검수의 연결을 확인하며, 미해결 필수 항목이 있으면 해당 항목을 점수와 무관하게 미완료로 보고하되 비핵심 조사 공백으로 초안 전달을 막지 않는다. 보고서 작업에는 research-report-contract의 총 8분 제한을 적용한다.

추가 에이전트나 승인 라운드를 만들지 않고 메인이 각 작성 턴 종료 전에 확인한다. 문장 품질은 기존 review.md가 담당한다.

| 확인 | 통과 근거 | 미통과 처리 |
|---|---|---|
| 진입 | 이 저장소 AGENTS.md와 main/dispatch/schedule을 실제 읽음 | 스킬만 읽었으면 실행 계약을 읽고 누락 단계부터 재개 |
| 위임 | 현재 단계의 역할별 실제 agent ID와 반환 결과 | ID 없는 역할 서술은 미실행. 도구 불가를 숨기지 않음 |
| 조사 | 공식 인재상·최신 공개 IR·직무 관련 제품/로드맵·출처·자료 공백 | 일부 검색을 통합 보고서 완료로 표시하지 않음 |
| 기업보고서 | Google Docs 문서·회사 탭 링크와 저장 후 본문 재조회 | 조사 완료와 미저장을 구분. 저장 가능하면 해당 턴에 실행 |
| 초안 | A/B 또는 사용자가 요청한 범위의 실제 본문 | 미작성 부분과 사실 확인 사항을 표시 |
| 초안 저장 | Notion 대상·버전·본문 재조회 결과 | draft-storage.md의 중복 방지·실패 보존 절차 적용 |
| 리뷰 | 해당 버전의 리뷰어 결과와 메인 통합 판단 | 다른 버전의 리뷰를 현재 버전 완료로 표시하지 않음 |

기업보고서는 prework 통합 결과를 받는 즉시 researcher 후속 작업으로 저장한다. 자소서 최종 선택을 기다리지 않는다. 사용자가 먼저 초안을 원하면 순서를 바꿀 수 있지만 보고서 저장은 미완료 작업으로 유지한다. 기존 저장 요청과 대상이 확인돼 있으면 다시 허락을 묻지 않는다. 명시적 저장 금지·보류는 따른다.

단계 상태는 `미시작 / 진행 중 / 완료 / 차단 / 사용자 요청으로 보류`로 구분한다. 저장 완료는 재조회까지 성공한 경우만 쓴다. 실패 시 원인·보존 위치·다음 조치를 알린다. timeout 뒤 재시도 전 원격 상태를 확인한다. 보고서와 초안을 같은 저장 상태로 묶지 않는다.

최종 답변에 이번 턴과 관련된 `실행한 역할 / 조사 상태 / Docs 저장 상태·링크 / 초안·Notion 상태·링크 / 남은 작업`만 짧게 표시한다. 질문 대기나 실제 접근 장애는 정상적인 중단 사유지만 '다음에 저장할게'는 실행 가능한 저장 단계를 생략할 사유가 아니다.

## 회귀 확인

- 상위 취업준비 프로젝트에서 '자소서 에이전트 써줘' 요청 → 이 저장소 진입, 실제 역할 호출.
- 기존 조사·초안이 있는 작업 재개 → 전체 재조사 대신 누락 단계 복구, 회사 탭 중복 없음.
- Docs 쓰기 성공 후 본문 누락 → 저장 완료 판정 금지.
- Notion 대상 미확인 → 초안 제공 유지, 필요한 위치만 질문, 과거 답안 덮어쓰기 금지.
- 단순 지침 디버깅 → 실제 기업보고서나 지원서를 임의 작성·저장하지 않음.

파일 점검은 지침 연결 검증일 뿐 실제 도구 실행 성공이 아니다. 배포 보고는 Git 반영, 로컬 진입 연결, 실제 Docs/Notion 저장 검증을 따로 표시한다.

보고서 총 8분, writing 문항당 작성·수정·검수·재검수·저장 총 5분 제한의 실제 소요시간을 점검한다. 기존 문안 수정에서 불필요한 전체 사이클을 재실행하지 않았는지 확인한다. 초회 전체 리뷰는 병렬 1회이며 수정사항은 반드시 담당 독립 리뷰어가 재검수한다. 최종 본문 버전과 재검수 통과 버전이 같은지 확인한다. 재검수 미완료는 검수 대기 초안으로 반환하며 미해결 사항과 저장 실패를 숨기지 않고 마감 시 문안을 먼저 반환한다.

기업보고서 누락 점검은 최초 저장 전에 Researcher가 필수 하위 항목별 본문 위치·출처·확인 상태 표를 작성하고 Main이 대조한다. 자소서 리뷰 단계에 보고서 완전성 점검을 미루지 않는다. 뒤늦게 발견된 비핵심 조사 공백은 후속 작업으로 기록하고 자동 재조사하지 않는다.
